# GT6 整合包阶段规划与魔改大纲

> 版本基线：Minecraft 1.7.10 / Forge 10.13.4.1614 / GregTech 6.17.06  
> 规划依据：当前实例 `mods/`、`scripts/`、`config/gt6bridge/` 与 `gt6bridge/DEVSTATUS.md`。  
> 定位：GT6 是主工业生产线；探索、魔法、存储和太空模组提供并行玩法或阶段性资源，不取代 GT6 的制造主线。

## 一、整合包目标

1. 让玩家从基础生存和资源认知出发，逐步建立 GT6 的采集、冶炼、加工、供能与自动化体系。
2. 用维度探索和魔法支线提供不同类型的材料、知识与挑战；它们可以丰富主线，但不应成为绕过 GT6 工业链的廉价捷径。
3. 把跨模组材料统一到 GT6 材料体系中；同类工业处理尽量集中到 GT6，保留其他模组没有替代方案的功能性配方。
4. 每个阶段都有明确的玩家目标、解锁条件、奖励/资源回流和可验证的完成标准。
5. 首先保证整合包能稳定启动、旧存档可控、配方可追踪；再扩展内容，避免同时改动大量系统后无法定位问题。

## 二、阶段总览

阶段名是本整合包的设计层级，不等同于 GT6 内部的电压等级或原版模组章节。具体机器、材料和数值应以当前安装版本的 NEI、GT6 配方表及实机测试为准。

| 阶段 | 玩家体验与核心目标 | 主线系统 | 内容边界 / 晋级信号 |
|---|---|---|---|
| 0. 稳定基线 | 建立可复现的客户端、脚本和配方环境 | Forge、GT6、MineTweaker、gt6bridge | 连续启停稳定；桥接报告、删除清单和临时测试配方均已核实 |
| 1. 生存与资源勘查 | 建立食物、工具、基础采集和探索能力 | 原版、Pam's、AgriCraft、Biomes O' Plenty | 能稳定获取基础矿物与食物；了解 GT6 的矿物/材料入口 |
| 2. 初级冶金与基础加工 | 从原矿和初级材料走向可重复的金属加工 | GT6 材料、手工/基础机器链 | 铜、锡、铁等早期材料可形成闭环；加工收益与投入可解释 |
| 3. 动力与机械化 | 把手工流程升级为可持续的动力生产与批量加工 | GT6 动力和机器；按需保留 IC2/TE 等功能 | 至少一条核心生产链可连续运行；不能因配方清理而失去必要用途 |
| 4. 电气化与自动化 | 建立稳定供能、机器分工和批量生产 | GT6 电力机器、AE2、GT6 桥接配方 | 关键材料链可自动化；存储/物流节省操作，不直接替代制造 |
| 5. 合金、化学与高阶材料 | 处理复杂材料、流体和副产物，准备远征资源 | GT6 高阶配方、材料桥接、流体链 | 核心合金与中间体有清晰配方；副产物有去向，避免无意义堆料 |
| 6. 魔法与异界探索 | 开展非工业玩法，取得独有知识、材料和挑战奖励 | Thaumcraft、Botania、Blood Magic、Witchery；Atum、Betweenlands、CandyCraft、TofuCraft、Alfheim | 每个异界模组只在本阶段开放；该维度的专属材料进入本阶段的 GT6 支线材料链 |
| 7. 星际工业与跨星球供应 | 将工业能力扩展到轨道、月球和其他星球 | Galacticraft、AmunRa、GalaxySpace、More Planets、Extra Planets、Advanced Rocketry | 每个星际模组只在本阶段开放；星球专属材料进入本阶段及后续终局的 GT6 材料链 |
| 8. 终局工程 | 汇总高阶材料、跨维度资源和大型自动化项目 | GT6 终局链、Hardcore Ender Expansion、Draconic Evolution、Avaritia 等 | HEE 只归属本阶段；终局异界材料用于高阶 GT6 部件/目标，不回流为低阶段捷径 |

### 维度模组与 GT6 材料的阶段唯一归属

以下按当前 `mods/` 中已启用的维度内容模组划分。表中每个模组只出现一次；原版主世界、下界和末地不属于独立维度模组，Biomes O' Plenty 也只改造主世界生成，因此不另占阶段。

| 唯一阶段 | 维度模组 | 本阶段纳入 GT6 的维度专属材料 | 接入 GT6 的方式与边界 |
|---|---|---|---|
| 6. 魔法与异界探索 | Atum | Atum 实测确认的矿物、金属和关键掉落；物品名待当前版本 NEI/矿词报告核定 | 先核对来源与用途；真实金属才绑定/建档，其他探索物只作为对应支线配方材料 |
| 6. 魔法与异界探索 | The Betweenlands | Octine、Syrmorite、Valonite 等候选专属材料 | 逐项核对当前物品、矿词和处理链；有对应 GT6 材料时绑定，缺少且确属金属时才评估建档 |
| 6. 魔法与异界探索 | CandyCraft | 糖果维度的专属资源与功能性掉落 | 食物、方块及装饰不建成 GT6 金属；只在有明确阶段用途时作为 GT6/支线配方输入 |
| 6. 魔法与异界探索 | TofuCraft | 豆腐维度资源、TofuSteel 等阶段性功能材料 | 以原物品参与阶段配方；`TofuMetal` 已在 `materials.csv` 标记跳过，不因维度归属而强制绑定成 GT6 金属 |
| 6. 魔法与异界探索 | Alfheim | Adaminite/Adamintite，以及实际确认有用的精灵维度材料 | 现有 `materials.csv` 已将拼写变体映射至 GT6 Adamantite；植物、宝石和装饰词条不按金属处理 |
| 7. 星际工业与跨星球供应 | Galacticraft | 月球、火星、小行星等区域的独有矿物和加工材料 | 用本阶段的航天、生命维持和 GT6 产线作为获取/加工前置；不把外星原矿直接等同于 GT6 成品 |
| 7. 星际工业与跨星球供应 | AmunRa | AmunRa 星球的专属资源 | 核对该模组实际注册物品和产地后，纳入本阶段 GT6 处理或阶段性配方 |
| 7. 星际工业与跨星球供应 | GalaxySpace | 星球矿物；`Cobaltum` 是已记录的 `Cobalt` 别名 | 复用现有材料映射；其他候选材料逐项确认注册者、矿词与用途后再决定绑定/建档 |
| 7. 星际工业与跨星球供应 | More Planets | Fronisium、Norium、Quontonium 等太空金属候选 | `create-candidates-metals.txt` 仅作候选清单；验证实际来源和配方后，才进入本阶段 GT6 材料表 |
| 7. 星际工业与跨星球供应 | Extra Planets | 各星球专属矿物与材料 | 按本阶段建立资源条目；已知词条中有与其他太空模组同名的情况，须按注册物品区分，不能仅凭词名合并 |
| 7. 星际工业与跨星球供应 | Advanced Rocketry | 小行星/自定义星球的陨铁与专属资源 | 以本阶段工业能力作为远征门槛；确认资源来源后纳入 GT6 处理，保留必要的火箭/星球功能配方 |
| 8. 终局工程 | Hardcore Ender Expansion | 末地扩展的高阶独有掉落与材料 | 先核对当前版本配方与来源，再作为终局 GT6 链的受控输入/目标；不提前放入阶段 6 或 7 |

**执行约束**

1. 维度模组按上表只归属一个阶段；一个模组跨多个世界/星球时仍按模组整体归属，不把同一模组拆到多个阶段。
2. 维度资源的“首次纳入/解锁阶段”与其 GT6 加工阶段一致；确实需要后续高阶加工时，可在后续阶段引用已解锁材料，但不得提前解锁该维度或重复给模组分配阶段。
3. 每种材料先记录来源模组、维度/星球、物品注册名、矿词、用途及 GT6 处理路径。优先绑定现有 GT6 材料；只有确认是有持续用途的真实材料且 GT6 无对应项时，才评估 `create:`。
4. “专属材料”不等于“新建 GT6 金属”：食物、植物、宝石、遗物、装饰品及混合物可作为原物品参与阶段配方，不应仅为纳入阶段表而创建材料。
5. 太空金属候选以 `tools/create-candidates-metals.txt` 为待核验清单，不直接视为已实装或已平衡；精确物品和配方未核实前，不添加猜测性配方。

## 三、各阶段魔改要点与完成定义

### 阶段 0：稳定基线与配方治理

**目标**

- 锁定 MC、Forge、GT6、MineTweaker、GT6Bridge 和关键内容模组版本。
- 使用独立测试世界验证配方，不用主存档承担首次测试风险。
- 确认配方来源、执行时机、回滚方法和服务端同步方式。

**当前实例需先处理**

- `config/gt6bridge/settings.csv` 当前为 `dryRun=false`、`removalDryRun=false`；`removals.csv` 对多个科技机后端使用 `*:*` 全量选择器。先切换干跑并记录每个后端的匹配/删除计数，再逐个验证哪些机器确实由 GT6 接管。没有等价替代的功能配方应保留。
- `enableAutoRules=false` 是合适的安全起点；不要因材料绑定成功就批量启用所有自动规则。
- `scripts/00_test.zs` 中有圆石加煤炭返还圆石的环境自检配方；完成脚本通路验证后应注释或移除，不能带入正式版本。
- `tools/GT6-魔改准备清单.md` 是早期准备阶段的快照，关于脚本目录为空、MTUtils 和配方桥接方式的描述已经落后于当前实例；当前实现以 `gt6bridge/README.md` 和 `gt6bridge/DEVSTATUS.md` 为准。

**完成标准**

- 连续 3 次启动、进入测试世界并正常退出，无新增启动崩溃。
- gt6bridge 运行期链接检查为零失败；材料绑定报告可解释，NEI 与机器实测通过。
- 每个计划禁用的非 GT6 机器都有 GT6 等价配方或明确的玩法替代；其余功能配方未被误删。
- 备份/回滚路径经过实际验证，服务器与客户端使用一致的脚本和配置。

### 阶段 1：生存与资源勘查

**目标**：让玩家理解环境、食物、基础采集和矿物分布，建立继续冶金所需的资源储备。

**魔改方向**

- 以原版生存、Pam's HarvestCraft、AgriCraft 和地形模组提供食物、种植与探索内容。
- 食物系统增加选择和稳定供给，不把饥饿惩罚变成纯粹的材料门槛。
- 早期任务强调“找到、识别、储备”资源，不提前赠送批量金属或高级机器。
- 地牢、遗迹和危险维度可提供一次性探索奖励，但奖励数量不应直接跳过初级加工。

**完成标准**：玩家能可靠取得基础生存物资，识别第一批目标矿物，并清楚下一步是建立冶金/加工链。

### 阶段 2：初级冶金与基础加工

**目标**：以 GT6 材料为主线，把“采矿—初级处理—冶炼—成形/零件”组织成可理解的生产链。

**魔改方向**

- 先查证当前版本已有的 GT6 原生配方；只为缺失环节补配方，不重复添加已有处理器会自动生成的配方。
- 外部模组注册的同类矿物、锭、粉、板和齿轮，优先通过 `materials.csv` 绑定现有 GT6 材料；确实是新金属且需要进入主线时，才考虑 `create:` 建档。
- 通过 NEI 和实机确认矿石、粉、锭及副产物链路；材料绑定不是新配方存在或平衡正确的证明。
- 用少量、可追踪的配方改动定义阶段目标，不在同一轮同时调材料、机器能耗和产率。

**完成标准**：至少一条从矿物到可用金属零件的 GT6 链路可以完整跑通，输入、产出、耗时和副产物都有记录。

### 阶段 3：动力与机械化

**目标**：让玩家从单件手工制造过渡到持续生产，动力来源成为真正的生产规划，而不是一次性门槛。

**魔改方向**

- 以 GT6 的实际机器和动力方案为基准编排阶段，不照搬其他 GregTech 版本的电压/机器假设。
- 适度调整机器配方，使早期自动化减少重复劳动，但不能免费复制稀有资源。
- 若保留 IC2、Thermal Expansion、EnderIO、Railcraft 或 Galacticraft 的机器，明确它们是功能补充还是替代路线；不要只按模组名全量清空。
- GT6 没有覆盖的物品处理、物流或特色玩法可以保留其他模组配方，并在 NEI/任务说明中解释其用途。

**完成标准**：至少一条基础材料线能持续生产；主要机器的输入输出、动力和配方来源均可查；未被保留的机器有清晰的 GT6 替代路径。

### 阶段 4：电气化与自动化

**目标**：把多个孤立机器连接为稳定的生产网络，引入物流和批量规划。

**魔改方向**

- 让 GT6 承担主要材料加工，AE2 主要承担存储、检索和自动化调度，不用廉价合成替代 GT6 的加工链。
- 评估各 mod 机器的重复功能，按机器类型和配方族逐步移除，保留独有机器、装饰/功能配方及没有 GT6 对应物的用途。
- 加入必要的熔炼、生成器和转换配方时，优先用经过核实的桥接 `recipes.csv` 规则；`autorules.csv` 保持逐条开启、逐条回归。
- 自动化目标应消耗玩家已经建立的生产能力，避免 AE2 在早期直接消除采集、供能和加工决策。

**完成标准**：关键资源能够稳定供给指定的中间件；自动化不会产生重复配方、无限循环或未经设计的资源复制。

### 阶段 5：合金、化学与高阶材料

**目标**：扩大生产链深度，引入多输入合金、流体、化学中间体和有意义的副产物管理。

**魔改方向**

- 逐种审核合金来源、组分比例、机器和流体要求，避免同一种材料存在明显更便宜的旁路。
- 对 GT6 未自动覆盖的熔炼/流体配方使用显式配置；对涉及燃料、温度或特殊机器机制的改动，先确认桥接 API 能否表达，不支持时不要用近似配方冒充。
- 给副产物设计可持续去向或明确的消耗目标，避免把大量随机副产物变成必须手工销毁的负担。
- 用稀有材料引导远征和下一阶段解锁，不使用不透明的纯数值堆叠制造门槛。

**完成标准**：阶段核心材料至少有一个可运行的生产/消耗闭环；NEI 中不存在低成本捷径；流体、能量、数量和概率均经实机复核。

### 阶段 6：魔法与异界探索（并行支线）

**目标**：给工业主线以外的玩家提供可持续的研究、仪式、战斗和探索玩法。

**模组定位**

- Thaumcraft 及其扩展、Botania、Blood Magic、Witchery：以研究、仪式、法术、资源收集和专属奖励构成不同支线。
- 阶段 6 维度模组（见唯一归属表）：承担环境挑战、独有材料和探索发现。
- 神秘扩展和其他非维度内容模组：作为支线内容来源，按依赖关系纳入，不自动视为必经主线。维度模组阶段归属统一见“维度模组与 GT6 材料的阶段唯一归属”，不在此处重复分配。

**魔改方向**

- 支线入口可在阶段 1–3 开放，但高价值工业回报按主线阶段控制。
- 魔法物品可以提供便利或独特能力；若能量产 GT6 关键金属、燃料或机器部件，应增加合理的材料/研究/探索前置。
- 维度矿物先在 `materials-known.txt`、桥接报告和实际物品数据中核对，再决定绑定、建档或跳过；装饰品、食物和泛称材料不要误当金属绑定。
- 维度专属资源严格按唯一归属表首次开放并接入对应阶段的 GT6 材料链；不因可提前进入或拥有后期配方而改变模组归属。
- 任务写明进入条件、危险提示、返回/补给方式及奖励用途，避免玩家因软锁无法继续。

**完成标准**：每条支线都能独立完成并有明确回报；支线奖励不会无意中跳过多个工业阶段。

### 阶段 7：星际工业与跨星球供应

**目标**：把行星探索转化为新的资源、环境与供应链挑战。

**魔改方向**

- 以 Galacticraft、AmunRa、GalaxySpace、More Planets、Extra Planets 和 Advanced Rocketry 的实际兼容状态为准；这些模组统一归属阶段 7。先解决维度/空间站 ID 和世界生成稳定性，再调内容。
- 航天器、生命维持、燃料和星球生存物资应消耗阶段 4–5 建立的工业产能。
- 星球独有矿物进入 GT6 阶段链前，先核对注册 mod、矿物词典名、GT6 材料及桥接结果；不存在合适材料时先评估是否值得新建，避免无节制增加材料表。阶段 7 首次开放这些材料，阶段 8 可在终局配方中继续消耗。
- 外星资源应提供新的工艺、材料或终局目标，不应只是一趟旅程换取大量现成终局物品。

**完成标准**：从起飞准备到首次有效资源回运的完整链路可在新测试世界复现；维度进入、返回与存档重载稳定。

### 阶段 8：终局工程

**目标**：提供一个跨工业、探索和支线内容的长期收束目标，而非简单堆叠稀有材料。

**魔改方向**

- Hardcore Ender Expansion、Draconic Evolution、Avaritia 等终局内容只归属阶段 8；其末地专属材料按验证后的来源进入 GT6 终局链。强力装备不能让剩余阶段失去意义。
- 终局项目由若干可分段验收的子目标组成，例如稳定供能、稀有材料供应、跨维度物流和大规模自动化。
- 奖励应改善终局效率、展示成就或解锁新玩法，不奖励能反向摧毁整条资源经济的无限产出。

**完成标准**：终局目标可解释、可追踪、可重复验证；完成后仍有建设、探索或挑战内容可玩。

## 四、配方与解锁的统一规则

1. **以 GT6 原生行为为先**：先查 GT6 配方和动态处理器；仅补缺口，不复制原配方。
2. **材料先统一，配方后补齐**：矿词绑定让 GT6 识别外部材料，但不等于所有 GT6 机器都能处理该物品；逐类核对处理器覆盖范围。
3. **移除规则必须可解释**：删除非 GT6 配方前，记录后端、选择器、受影响配方数量、GT6 替代项和回滚方式。全量 `*:*` 只可在确认该机器所有配方均无保留价值后启用。
4. **自动规则逐条启用**：每条 `autorules.csv` 规则先干跑，再核对 NEI 与实机；不可用一个“全开”代替设计审核。
5. **先删后加，但不盲目删**：CraftTweaker 脚本按主题分组，删除与替代配方成对维护；GT6 配方改动优先走已验证的桥接配置。
6. **所有价格都用生产链验证**：比较原料稀有度、处理步骤、时间、能耗、概率、副产物和物流成本，避免仅比较输入物品数量。
7. **每次只改一类问题**：按阶段/配方族分批修改，记录 NEI 页面、桥接报告和测试结果，保留单项回退能力。

## 五、任务书与玩家引导结构

如果采用 Better Questing 作为任务书，建议每个阶段保持同一章节模板：

1. **阶段说明**：本阶段要解决什么生产或探索问题。
2. **关键知识**：新材料、机器、动力、维度规则与风险。
3. **必做里程碑**：只设置推进主线所需的最少目标。
4. **可选挑战**：支线、效率优化、探索发现和收集，不阻塞主线。
5. **解锁与奖励**：说明奖励为何有用，避免奖励直接替代下一阶段整条产线。
6. **故障排查**：NEI 查询、GT6 机器用途、维度返回和服务器同步的基本提示。

任务书只负责解释和追踪，不应成为唯一的配方信息来源；配方仍须在 NEI 中可见、可反查。
